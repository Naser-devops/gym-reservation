# Gym Reservation — PHP / PDO / MySQL

نظام إدارة حجوزات نادي رياضي مع واجهة داكنة، صور `hero.png` و`auth.png`، وتأثير Three.js، وحركات GSAP ورسوم Chart.js.

## ما الذي يقدمه الموقع؟

- **User:** تسجيل حساب والدخول والخروج؛ الاطلاع على المواعيد المستقبلية والسعة المتبقية؛ حجز مكان بحالة Pending وملاحظة اختيارية؛ عرض الحجوزات وإلغاؤها قبل وقت البداية.
- **Admin:** إحصائيات وجدول الحجوزات؛ الموافقة والرفض والإلغاء؛ تفعيل/تعطيل المستخدمين؛ إنشاء/تعديل/تفعيل/تعطيل وحذف منطقي للمواعيد.
- **التحقق:** جلسات دخول، CSRF، تهريب HTML بـ `e()`، استعلامات PDO المجهزة، وفحص السعة داخل Transaction مع قفل `FOR UPDATE`.
- **سلوك مقصود:** الحجز المرفوض أو الملغى لا يستهلك مقعدًا، لكن لا يمكن حجز نفس الموعد مجددًا لنفس المستخدم بسبب `UNIQUE(user_id,time_slot_id)`.

## تشغيل محلي آمن (XAMPP)

1. خذ نسخة احتياطية من **مجلد المشروع**، وصدّر قاعدة `reservation_db` الموجودة عبر phpMyAdmin قبل أي ترحيل.
2. شغّل MySQL من XAMPP. إذا كانت القاعدة جديدة تمامًا فقط، استورد `database/schema.sql`؛ **لا تستخدمه لمسح بياناتك الحالية**.
3. للقواعد القديمة نفّذ `php scripts/migrate.php` بعد النسخة الاحتياطية؛ لا تشغّل السكربت إلا عند الحاجة.
4. افتح Terminal داخل مجلد المشروع الذي يحتوي `index.php`، وشغّل:

   ```bash
   php -S localhost:8000 router.php
   ```

5. افتح `http://localhost:8000/`؛ الصفحة الرئيسية تعمل الآن حتى عند توقف MySQL، لكن Login والحجوزات تحتاج قاعدة البيانات.
6. سجّل حسابك ثم ادخل. لترقيته إلى مدير، نفّذ من Terminal:

   ```bash
   php scripts/promote_admin.php your-real-email@example.com
   ```

7. اخرج وادخل من جديد، ثم افتح `?page=admin-classes` وأضف موعدًا مستقبليًا بسعة أكبر من صفر. يظهر للمستخدم في `?page=classes`.

**متطلبات:** PHP 8.1 أو أحدث مع `pdo_mysql` وMySQL/MariaDB بجدول InnoDB. مثال إعدادات XAMPP المحلي: `127.0.0.1`، اسم القاعدة `reservation_db`، المستخدم `root` وكلمة مرور فارغة فقط إن كانت هذه إعدادات جهازك. لا تستخدم ذلك في الإنتاج.

## قبل النشر العام — إلزامي

- انشر فقط على استضافة تدعم PHP وMySQL وHTTPS. لا ترفع نسخة ZIP وتفترض أنها أصبحت محمية تلقائيًا.
- عيّن متغير البيئة `APP_ENV=production` وأيضًا `DB_HOST`, `DB_NAME`, `DB_USER`, `DB_PASS` **على مستوى الاستضافة**. في وضع الإنتاج لن يتصل المشروع بقاعدة بيانات إذا لم تكتمل هذه المتغيرات. يجب أن تكون كلمة مرور الإنتاج غير فارغة، والمستخدم محدود الصلاحيات.
- **ملاحظة مهمة:** `.env.example` ملف تعليمات فقط؛ الكود **لا يقرأ `.env` تلقائيًا**. لا ترفع أسرار DB أو `.env` إلى GitHub عام.
- اجعل HTTPS متاحًا وإجباريًا، واضبط النطاق وجلسات PHP بشكل مناسب. وضع الإنتاج يفعّل `Secure` لملف تعريف ارتباط الجلسة، لذا **لن تستمر الجلسات على HTTP غير المشفر**.
- إذا استخدمت Apache مع مجلد المشروع كاملًا كـDocumentRoot، يجب تفعيل قراءة `.htaccess` (`AllowOverride` المناسب). ملفات `.htaccess` داخل `app/`, `config/`, `database/`, `docs/`, `resources/`, `scripts/`, `storage/`, `tests/` ترفض الوصول المباشر إليها على Apache 2.4 عند تفعيلها، إضافة إلى حماية `.htaccess` الرئيسي. اختبر مسارات خاصة عبر HTTP وتأكد من 403/404 قبل قبول النشر.
- لو استخدمت Nginx أو استضافة لا تقرأ `.htaccess`، **اضبط قواعد الحماية على مستوى الخادم** بدل الاعتماد على هذه الملفات. لا تستخدم `php -S` بدون `router.php` لعرض الموقع على الإنترنت.
- تحديد محاولات الدخول يستخدم ملفات في `storage/login-limits/` مع الأقفال `flock()`؛ يجب السماح لعملية PHP بالكتابة هناك. على أكثر من خادم استخدم مخزنًا مشتركًا للحد من المحاولات؛ عند تعذر الكتابة يبقى حد الجلسة فقط ويظهر تحذير في error log.
- الصور والمكتبات الخارجية: Three.js وGSAP وChart.js وخطوط Google تحتاج إنترنت من جهاز الزائر. اختبر ذلك، وفكر في الاستضافة الذاتية للملفات عند الحاجة.

## اختبار المشروع عمليًا قبل النشر

1. تسجيل حساب جديد، Login، Logout، كلمة مرور خاطئة، محاولة ثامنة خاطئة ثم الحظر.
2. أضف حصة مستقبلية من Admin، ثم افتح Available Slots من حساب User.
3. احجز مرة، تحقق من Pending، جرّب تكرار الحجز، اختبر اكتمال السعة بحسابات مختلفة.
4. أكد الحجز ثم تحقق من الحالة، جرب Cancel قبل البداية، وReject لحجز آخر.
5. عطّل حساب مستخدم، جرّب الدخول والصلاحيات، وتأكد أن مستخدمًا عاديًا لا يستطيع فتح صفحات Admin.
6. جرب تعديل السعة والتاريخ وحذف الحصة بالقيود المطلوبة.
7. اختبر `home`, `login`, `register`, `admin` على الكمبيوتر والهاتف، وحركة Three.js بعد Back/Forward.
8. افحص أدوات المطور Console وNetwork وأي أخطاء اتصال أو ملفات 404.

راجع `docs/test-report.md` لمعرفة نطاق الاختبارات المنفذة وحدودها. **لم يُختبر التكامل الحقيقي لـMySQL داخل بيئة إعداد الحزمة؛ جرّبه بنفسك قبل نشر الرابط.**

## خريطة الملفات للتعلم

- `index.php`: مدخل الطلبات والصفحات
- `app/Core/Database.php`: اتصال PDO
- `app/Core/LoginRateLimiter.php`: تقييد محاولات الدخول بين الجلسات باستخدام ملفات
- `app/Core/helpers.php`: الحماية والدوال المساعدة
- `app/Models/`: البيانات وقواعد الحجز
- `app/Controllers/`: عمليات المستخدم والمدير
- `app/Middleware/`: الصلاحيات
- `resources/views/`: واجهات PHP
- `public/assets/`: الصور وCSS وJavaScript
- `database/schema.sql`: مخطط إنشاء جديد، لا بيانات تجريبية
- `scripts/`: أدوات تشغيل من Terminal فقط

الملفات غير المستخدمة التي حُذفت في هذه النسخة مسجلة في `docs/changes-ar.md`.
