# طريقة إضافة حزمة Gym Reserve إلى GitHub

هاي الحزمة جاهزة لترتيب مستودع `Naser-devops/gym-reservation`.

## الملفات

- `README.md`: ضعه في **جذر المستودع** (Root)، بجانب مجلد `gym-reservation3`.
- `docs/screenshots/`: ست صور حقيقية من واجهة المشروع (بدون إيميلات ظاهرة في اللقطات المختارة).
- `docs/architecture/aws-architecture.png`: صورة AWS Architecture للـREADME.
- `docs/architecture/aws-architecture.svg`: النسخة المتجهية من المخطط (يمكن تكبيرها بدون فقدان جودة).
- `screenshots-preview.jpg`: معاينة مجمعة للصور؛ للعرض فقط، **غير مطلوبة في GitHub**.

## طريقة الإضافة

1. فك ضغط ZIP عندك على جهاز Windows.
2. افتح مستودع GitHub: https://github.com/Naser-devops/gym-reservation
3. ضع `README.md` و**مجلد `docs` بالكامل** في جذر المستودع بنفس مساراتهما الظاهرة أعلاه؛ لا تغيّر أسماء الصور كي تعمل الروابط الموجودة في README.
4. أضف الملفات باستخدام واجهة GitHub أو مستودع محلي ثم Commit/Push عندما تحب.
5. افتح الصفحة الرئيسية للمستودع وتأكد أن الصور الست والمخطط يظهرون داخل README.

## تنبيه بخصوص GitHub Push المؤجّل

على EC2 يوجد Commit محلي محفوظ باسم `04769b8` يحتوي تكامل قاعدة البيانات في AWS وملفات Composer، **لكن عملية Git Push السابقة فشلت بسبب المصادقة**. لذا قد تكون نسخة GitHub الحالية أقدم من بعض التغييرات الموجودة على EC2.

تقدر تنشر README والصور الآن؛ لكن لاحقًا، قبل الاعتماد على المستودع لإعادة نشر التطبيق، ارفع ذلك الـCommit أيضًا وتأكد من حالة `main`. إذا عدّلت GitHub من المتصفح، لازم تزامن التغييرات مع نسخة EC2 قبل عمل Push حتى تتجنب التعارضات. لا تستخدم `git push --force`.

**حماية الخصوصية:** لا ترفع ملفات `.env` أو كلمات المرور أو رموز الدخول أو مجلد `vendor/` أو ملفات نسخ قواعد بيانات تحتوي على معلومات شخصية.
